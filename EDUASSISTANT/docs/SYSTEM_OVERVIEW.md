# EDUASSISTANT System Overview

EDUASSISTANT is Team 1's MLAI Hackathon 2026 submission for the VNG Track, Option A: The Escalation Referee.

## Scope

The only supported use case is `MILITARY_SERVICE_CONFIRMATION`: an internal workflow for processing student-status confirmation requests that may support military-service deferment paperwork. Its printout is an internal workflow record, not an official certificate. This application does not decide whether a person is legally eligible for deferment. `AUTO_APPROVE` means the internal workflow found enough trusted facts to process automatically; it is not approval from a military authority.

Live frontend: <https://edu-sp.pages.dev>
Judge page: <https://edu-sp.pages.dev/judge>

## Runtime shape

- Frontend: React and Vite, published on Cloudflare Pages.
- Backend: Python FastAPI, started with `python -m uvicorn backend.server:app --host 0.0.0.0 --port 3001`.
- Database: PostgreSQL through `DATABASE_URL`.
- Address extraction: Google Gemini first, OpenRouter fallback when configured, then deterministic parser fallback.
- SIS facts: Admin-managed internal demo registry. No external university SIS connector is present.

## Decision flow

1. The student submits a permanent-address claim.
2. Address AI returns parsed fields, confidence, provider/model, and call/fallback provenance.
3. The Rule Engine checks institutional trust provenance, identity, academic facts, address completeness, conflicts, and AI provenance.
4. It either routes the case to a human reviewer or marks it eligible for internal automatic processing.
5. Reviewer actions and Admin SIS changes are written to the audit trail.

The five escalation categories (`OWNERSHIP_UNCLEAR`, `FACT_UNKNOWN`, `DATA_CONFLICT`, `AUTHORITY_REQUIRED`, and `POLICY_OUT_OF_SCOPE`) are Team 1's implemented taxonomy, not a required Hackathon naming standard.

## Institutional trust

Production rules accept an external record only with `sourceType=EXTERNAL_INSTITUTIONAL_SIS` and `verificationStatus=EXTERNAL_VERIFIED`. Internal records use `sourceType=INTERNAL_DEMO_SIS`; Admin confirmation sets `verificationStatus=ADMIN_VERIFIED_DEMO` and means the facts were checked for this demo workflow only. This trust is disabled by default in production and is controlled by `ALLOW_ADMIN_VERIFIED_DEMO_SIS`.

Benchmark and Verify Harness fixtures use `SYNTHETIC_TEST_SIS` plus `TEST_VERIFIED`. They are accepted only when the caller passes an explicit deterministic test evaluation context. Production routes do not pass that context.

## Evaluation paths

| Path | Cases | Network or database writes | Purpose |
| --- | ---: | --- | --- |
| Verify Harness | 9 | None | Fast deterministic Rule Engine check |
| Track A Decision Benchmark | 18 | None | Fixed synthetic scenarios for escalation-policy metrics |
| Live AI E2E sanity check | 5 | Gemini and configured OpenRouter fallback | Optional address extraction check; separate from Track metrics |

The Track benchmark writes its latest result to `benchmark/results/latest.json` and `.csv`. It reports `benchmarkType=DETERMINISTIC_TRACK_A_DECISION_BENCHMARK` and `aiCallsPerformed=false`. The scenario set is fixed but is not described as independent or held out.

## Integrity token and confidence limits

HMAC-SHA256 is an integrity authentication token that can detect changes when checked with the shared secret. It is not a PKI signature or a legal digital signature. The AI confidence score is generated by the model and has not been statistically calibrated on a production dataset.
