# Measurement Plan

Keep each evaluation path separate. AI sanity checks do not measure Track A
routing, and synthetic evidence is not user validation.

## A. Verify Harness — 9 deterministic checks

`POST /api/verify/run` runs nine in-memory Rule Engine cases. It makes no AI or
network calls, performs no database reads or writes, and does not mutate the
adaptive threshold. It is a fast functional check, not a model-accuracy estimate.

## B. Fixed Synthetic Development Benchmark — 18 cases

Run `benchmark/run_benchmark.bat`. It evaluates the fixed scenarios in
`benchmark/fixed_synthetic_cases.json`, calls no AI provider, and writes
`benchmark/results/latest.json` and `latest.csv`. The JSON records its run ID,
timestamp, exact dataset SHA-256, raw counts, denominators, rates, and case
results. This fixed scenario set is not independent, held out, or production
validation.

Use these exact formulas:

- `decisionAccuracy = correctCases / totalCases`
- `automationRate = AUTO_APPROVE decisions / totalCases`
- `escalationRate = ESCALATE_TO_HUMAN decisions / totalCases`
- `missedEscalationRate = missedEscalationCount / expectedEscalations`
- `unnecessaryEscalationRate = unnecessaryEscalationCount / expectedAutoApprovals`

Report percentages with the raw numerator and denominator. Never change the
denominator for missed or unnecessary escalation to all cases.

## C. Frozen Holdout — manual final evaluation

The frozen v1 dataset has 36 static synthetic scenarios in
`benchmark/holdout/track_a_holdout_v1.json`. Its expected labels are written in
the dataset, not generated by the Rule Engine. `manifest.json` freezes the exact
SHA-256 and count. The runner checks the hash before evaluation, uses only the
Rule Engine with deterministic synthetic context, and writes aggregate and
case results to `benchmark/holdout/results/`.

Run manually with `benchmark/run_holdout_eval.bat` after implementation
work is complete. Only the explicit manual holdout command reads this dataset;
normal application requests and routine CI do not. Do not tune on v1 or edit it after seeing its results. If a
correction is needed, publish a new version and explain it in the manifest.
This set is separate from the 18-case development benchmark. It was authored
for this repository; it is not claimed to be externally or independently
authored.

Judge Mode displays holdout metrics only when the result matches the frozen
manifest. If no result file exists, it says the final holdout has not been run.

## D. Optional Live AI sanity check — not a Track A metric

`benchmark/run_live_ai_eval.bat` calls configured live AI providers to
check address extraction. It can incur provider usage and requires network and
secrets. It does not replace missed-escalation or unnecessary-escalation rates,
and it is not an official Track A score.

## E. User Validation — PENDING

Real participant sessions have not been conducted for this task. Keep status
**PENDING** until real people consent, complete the sessions, and provide
recorded evidence. Do not invent participants, quotes, screenshots, scores, or
product improvements.
